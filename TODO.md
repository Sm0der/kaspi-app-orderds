## 📊 Данные в БД

**Orders Table:**
- `kaspi_order_id` — ID заказа в Kaspi
- `status` — статус заказа (принят/собран/и т.д.)
- `delivery_date` — дата доставки (для определения срочности)
- `urgency` — вычисляемое поле (overdue/today/soon/upcoming)
- `raw_data` — полный ответ от Kaspi (JSON)

**Order Items Table:**
- Позиции заказа с фото, количеством, артикулом

**Sync History:**
- Логирование каждой синхронизации

**Push Subscriptions:**
- Хранит endpoint для Web Push API

## ⚠️ Важные замечания

1. **Kaspi API credentials** — никогда не коммитить `.env` файл в публичный репозиторий
2. **HTTPS для push** — в продакшене нужен HTTPS; локально работает на localhost
3. **Rate limiting** — Kaspi может отправлять 429 (Too Many Requests), есть retry logic
4. **Photo URLs** — если Kaspi не отдает прямые URL, нужно либо:
   - Доставать из карточки товара (отдельный запрос)
   - Сопоставлять с собственной БД картинок
5. **Timezone** — текущая логика срочности использует системное время, может быть нужно учитывать часовой пояс Казахстана (UTC+6)
